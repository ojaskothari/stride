# Decision log

Design decisions and the evidence behind them, newest last. When a measurement changes a decision,
the old entry stays and a new one says what changed and why.

Milestones referenced below: **M1** timer product · **M2** workout plans · **M3** noise-study data ·
**M4** benchmark · **M5** Whisper fine-tuning · **M6** real-world validation · **M7** earbud trigger.

| Date | Decision | Why |
|---|---|---|
| 2026-11-21 | Python, on-device faster-whisper, rule-based intent parser | Instant, offline and private. The command set is small and closed, so a deterministic parser is predictable and fully testable. |
| 2026-11-21 | No LLM agent or hosted LLM API | A closed command set doesn't need one, and a network round trip breaks the latency and offline goals. The hard problem is recognizing speech in noise, so that's where the ML work goes. |
| 2026-11-21 | Noise study: own recordings + public noise, mixed at controlled SNRs | Feasible solo and a standard method. Labels carry over from the clean clips, so thousands of test clips come labeled for free. |
| 2026-11-21 | Whisper LoRA fine-tuning (M5) after the benchmark; custom wake word is optional | Completes the measure → diagnose → train → re-measure loop. |
| 2026-11-21 | A fine-tuned model must beat vocabulary prompting + fuzzy matching on held-out speakers, noise and phrasings | Beating raw Whisper alone would overstate the gain. Held-out sets catch memorization. |
| 2026-11-21 | src layout (`src/stride/`), hatchling; CI on Python 3.11 + 3.12 × Ubuntu + macOS | Tests run against the installed package, not the working directory. 3.11 is the floor (`tomllib`). |
| 2026-11-21 | Config defaults live in code; `config.toml` is a partial override; unknown keys are errors; a test pins `config.toml` to the defaults | A typo silently ignored mid-workout is the worst failure mode, and the documented file can't drift from the code. |
| 2026-11-21 | mypy `--strict` from the first commit | Cheap to keep strict from the start, expensive to retrofit. |
| 2026-11-21 | Live-audio dependencies (faster-whisper, sounddevice, numpy) are an optional `[audio]` extra | Core logic and CI stay lightweight. Pure-logic tests never import audio libraries. |
| 2026-11-21 | `small.en` excluded from live use; kept in the M4 grid as an accuracy ceiling | Measured 1,086 ms median STT on the target laptop, above the 1.0 s end-to-end budget on its own. `tiny.en` 146 ms, `base.en` 316 ms. [spikes §2](spikes.md#2-faster-whisper-latency-2026-11-21) |
| 2026-11-21 | Latency is logged per stage (silence hangover, STT, cue start); the end-of-speech detector and model are chosen in M4 with data | The 600 ms silence hangover is the biggest single cost. `base.en` projects to ~950 ms against the 1.0 s target, too close to call without real measurements. |
| 2026-11-21 | Mic calibration discards the first ~200 ms of a stream; an all-zero signal is reported as missing mic permission | Startup frames measured at −173 dBFS (digital silence), and macOS denies mic access silently. [spikes §3](spikes.md#3-microphone-access-2026-11-21) |
| 2026-11-21 | Dev venv lives at `.venv.nosync` (symlinked as `.venv`) | iCloud Drive re-applies the `hidden` flag to the editable-install `.pth` file, which Python 3.12+ skips, breaking `import stride`. iCloud ignores `.nosync` names. |
| 2026-11-21 | Cues are pre-rendered clips (`say -o`, cached on disk, keyed by phrase + voice, rendered in parallel on first run) and played in-process via sounddevice. Common confirmations ("Resting 2 minutes 15", rests at 15 s steps to 10:00) are rendered whole; rare ones are composed from fragments. Cues start early by the output stream's reported latency. `pyttsx3` dropped. | Spawning `say` per cue measured ~1.2 s overhead (~630 ms is process startup); pre-rendered playback starts in ~35 ms and every countdown digit fits its 1 s slot. pyttsx3 has the same startup cost on macOS. Rejected: accepting the delay (breaks countdown and 1.0 s target); in-process `AVSpeechSynthesizer` via PyObjC (new heavy, macOS-only dependency). [spikes §1](spikes.md#1-speaking-cues-with-macos-say-2026-11-21) |
| 2026-11-21 | Parser does formatting normalization only (digits/words, `1:30`, `3-minute`, fillers); no fuzzy or phonetic matching. Bare numbers ≤ 10 are minutes ("rest 3"), larger are seconds ("rest 90"). | Fuzzy matching is an M4 baseline; folding it into the parser would hide how often raw Whisper mishears. The ≤ 10 rule matches how athletes say rests. |
| 2026-11-21 | Timer is a pure state machine driven by `now`; pending cue marks are rebuilt on start and on every add. Marks within 3 s of now are skipped; after a stall only the latest overdue cue is spoken. | One rebuild rule covers min-rest gating (2:00 only if total ≥ 3:00), re-arming after "add", and skipping marks right after a confirmation. Stacked late cues ("5 4 3") are worse than one on-time cue. |
| 2026-11-21 | Cue catalog rendered in batches (one `say` per ~79 phrases, split on silence, count-checked, per-phrase fallback). | 315 clips: 162 s → 55 s on first run. [spikes §4](spikes.md#4-rendering-the-cue-catalog-2026-11-21) |
| 2026-11-21 | Stale cues are dropped at the time they'd be *heard* (now + output latency): countdown digits > 0.5 s late, other cues > 3 s late. "Go" is never dropped. Speech output is held while the mic is listening. | A late digit is worse than silence. Holding output keeps stride from talking over the user or into its own mic on laptop speakers. |
| 2026-11-21 | Energy VAD with a rolling 20th-percentile noise floor, updated only while idle; onset needs 60 ms above floor + 10 dB. A second tap ends the utterance immediately. | The floor follows the environment (crowds come and go) without learning the user's voice. 60 ms rejects tap/click transients. The second tap skips the 600 ms silence wait, the largest latency cost. |
| 2026-11-21 | Latency is logged when the reply *starts playing*, plus output latency: `end_to_end_s` = reply audible − end of speech. | Measures what the athlete experiences, not when the code returned. |
| 2026-11-21 | Whisper: beam 5, local model preferred (offline), `HF_HUB_DISABLE_IMPLICIT_TOKEN=1`, warm-up decode at load. | Beam 1 saves ~5% (≈ 19 ms on base.en) at unmeasured accuracy cost; revisit in M4. ctranslate2 also reports an experimental Apple GPU (MPS) backend "often 2x+ faster": a latency lever to measure in M4. |
| 2026-11-21 | `audio.max_utterance_s` 6.0 → 4.0 | First live sessions: commands took 1–2 s to say, but nearby noise kept the VAD open until the 6 s cap, the longest pause the author noticed. The longest realistic command is ~3 s. A cut-off command would show up in the log as `max_length` with a garbled transcript. |
